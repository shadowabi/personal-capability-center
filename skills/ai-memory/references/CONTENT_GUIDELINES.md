# 内容存储指南

## 核心原则

**记录能力到数据库**

当用户提供对话内容时，应该记录**对话中形成的能力**，而不是简单地保存对话或提炼知识点。

### 什么是能力？

对话不仅仅是知识，而是**能力**。因为对话包含了：
- 我掌握了什么（不是被告知"xxx是xxx"，而是真正理解）
- 得出了什么深刻的思考（有了自己的理解和洞察）
- 为什么会这样想（思考路径、关键节点、认知跃迁）

### ai-memory的任务

- **记录能力到数据库**
- 只有足够多的能力记录，才能做体系化分析
- 从多个能力记录中，生成能力成长轨迹、能力评估、成长建议

### 能力 = 掌握的内容 + 深刻思考 + 思考路径

**掌握的内容**：我真的理解并掌握了什么
**深刻思考**：得出了什么深刻的洞察
**思考路径**：为什么会这样想（从错误到正确的转变过程）

## 工作流程区分

### 保存阶段（当前）
- **保存的是"能力"**（完整的认知跃迁过程）
- 对话即能力 - 对话本身形成了能力
- 包含：我掌握了什么、深刻思考、思考路径、关键节点

### 盘点阶段（后处理）
- **从能力记录中进行体系化**
- AI分析数据库中的所有能力记录
- 生成：能力成长轨迹、技能提升总结、能力评估、成长建议、能力体系图

**为什么这样设计？**
- 保存时：记录能力本身（包含掌握的内容、深刻思考、思考路径）
- 盘点时：从多个能力记录中，进行体系化分析和总结
- 复用时：既能查看完整的思考过程，又能获得体系化的能力分析

## 与笔记工具的区别

| | 笔记工具 | 能力中心 |
|---------|---------|---------|
| **存储内容** | 知识点（如"市盈率=股价/每股收益"） | 对话（包含思考过程、引导提问、认知跃迁） |
| **能力提取** | 手动整理，零散 | AI自动盘点，体系化 |
| **复用方式** | 查笔记，回忆 | 快速找到类似思考路径 + 提炼的能力模块 |
| **成长追踪** | 无 | 月度/年度能力盘点，看成长轨迹 |

## "对话即能力"的理念

当AI使用"引导式思维"与你交互时，对话本身就变成了深度思考的过程。

**对话是能力的载体**：
- 保存对话 = 保存能力
- 月度盘点 = 从对话中提炼能力
- 复用能力 = 找到类似对话 + 使用提炼的方法论

## 存储结构

### 数据库字段说明

| 字段 | 用途 | 内容建议 | 长度建议 |
|------|--------|---------|----------|
| **title** | 一句话总结，3秒抓住核心 | 描述认知跃迁（从"X"到"Y"） | 50-100字符 |
| **summary** | 结构化总结，快速浏览 | 问题背景、探索过程、最终方案 | 100-500字符 |
| **details** | 完整思考过程，包含关键路径 | 错误认知、矛盾点、引导提问、认知突破、结论建立 | 根据需要，不限长度 |

## 适用场景

### 场景1：苏格拉底式引导对话（推荐）

当对话包含AI引导你思考的过程时，应该记录**掌握的能力**（抽象层）以及体现在具体问题的深刻洞察（表象），包含认知转变过程（我是通过什么方法才掌握的）。

**核心概念**：
- **能力**（抽象层）：底层逻辑，可复用于其他场景
- **深刻洞察**（表象）：能力体现在具体问题的认识
- **认知转变**：如何从错误认知走向正确能力

**✅ 正确做法：记录能力 + 深刻洞察 + 认知转变**

```python
title = "股票估值：掌握动态估值和多维度综合判断能力"

summary = """问题背景：市盈率越低越好？遇到指标矛盾时无法判断

掌握的能力：
1. 动态估值能力：理解指标反映未来预期而非静态现状
2. 预期管理能力：理解市场预期及其变化对价格的影响
3. 多维度综合判断能力：不看单一指标，综合评估
4. 概念区分能力：区分表面相似但本质不同的概念"""

details = """问题背景：
- 最初理解：市盈率越低越好，便宜=划算
- 已有认知：增长率比PE更重要（这个已经对了）
- 混淆概念：把"亏损"和"烧钱换增长"混淆

---

我掌握的能力：

能力1：动态估值能力
能力定义：理解指标反映的是未来预期而非静态现状
体现在深刻洞察：
1. 市盈率低不等于被低估，可能本身就是价值低
2. 市盈率反映未来预期，不是当前便宜

认知转变过程：
- 原本认知：市盈率越低越好，10倍比100倍更值得投资
- 引导提问："清仓大甩卖为什么便宜但没人买？这和被低估有什么关系？"
- 突破点：街边大甩卖便宜但没人买，是因为本身质量不好，不是被低估；B公司是上升期，A公司是下降期
- 新认知：市盈率低不等于被低估，可能本身就是价值低

---

能力2：预期管理能力
能力定义：理解市场预期及其变化对价格的影响
体现在深刻洞察：
1. 预期被打破会导致股价大跌（增长率从30%降到5%）
2. 市场给30倍PE是赌未来增长，赌错了就是被高估

认知转变过程：
- 原本认知：已经正确选择了B公司，但没考虑预期变化
- 引导提问："如果B公司未来3年增长30%，第4年突然降到5%，30倍PE还合理吗？"
- 认识到：增长率突降说明现状已改变，已到顶了
- 突破点：市场给30倍PE是赌未来增长，如果增长率从30%降到5%，预期被打破，股价必然跌
- 类比：你预期年终奖30万，结果只有5万，整个人都不好了
- 新认知：市盈率反映预期，预期落空会导致股价大跌

---

能力3：多维度综合判断能力
能力定义：不看单一指标，综合评估多个维度
体现在深刻洞察：
1. 增长率比市盈率更重要（这个一开始就对了）
2. 投资价值排序：被低估的好公司 > 被高估的好公司 > 被低估的公司

认知转变过程（关于投资价值排序）：
- 引导提问："投资时，买便宜和买好公司，哪个更重要？"
- 认识到：买好公司更重要，正如清仓大甩卖未必卖得出去一样
- 建立排序：被低估的好公司 > 被高估的好公司 > 被低估的公司
- 理由：市盈率指标可能会失效，关键在于公司是不是真的增长；市盈率低，有可能买到一些被低估的
- 新认知：买好公司是基础，便宜是锦上添花，不能本末倒置

---

能力4：概念区分能力
能力定义：区分表面相似但本质不同的概念

1. 区分"亏损"vs"烧钱换增长"
2. 区分"静态便宜"vs"动态价值"

认知转变过程（关于亏损vs烧钱换增长）：
- 原本认知：高销售额但持续亏损的公司值得投资，参考智谱公司

- 引导澄清："亏损公司和烧钱换增长的公司是两回事，有什么区别？"
- 引导提问："一家餐厅月销售额100万，每月亏损10万，这是好生意吗？"
- 认识到：亏损公司和烧钱换增长是两回事；持续亏损只能靠投资续命，用完还不盈利就不行了
- 引导提问："销售额高但不赚钱，说明什么能力有问题？"
- 突破点：高销售额不赚钱可能是成本控制问题
- 新认知：区分"亏损"vs"烧钱换增长"，要判断可持续性

---

能力定义：理解市场给确定性高的公司更高估值

1. 茅台高PE因为市场相信他能持续盈利增长
2. 确定性=低风险，不确定性=高风险，值得支付溢价

认知转变过程：
- 引导提问："茅台PE为什么长期维持30-50倍，而有的公司PE只有5-10倍？"
- 认识到：茅台市盈率高，很大程度上大家知道或相信他是能赚钱的，而且能一直增长下去
- 突破点：确定性=低风险，不确定性=高风险；市场给确定性高的公司"确定性溢价"
- 类比：买保险愿意多付保费，因为买了确定的保障
- 新认知：市场给确定性高的公司更高估值"""
```

## 能力记录的核心要素

### 每个能力应包含：

1. **能力定义**：这个能力的本质是什么
2. **体现在深刻洞察**：用1-2条具体场景说明这个能力
3. **认知转变过程**：从错误到正确的转变路径
   - 原本认知：开始时的错误认知
   - 引导提问：AI提出了什么关键问题（**如实记录**）
   - 突破点：在哪个时刻突然明白了
   - 新认知：最终形成的新认知
   - 类比验证：用什么生活场景验证了理解

### 精简原则：

- **只记录经典问题**：避免重复，选择最能体现认知跃迁的问题
- **聚焦关键转折**：详细记录从错误到正确的转变点
- **如实记录引导**：标注"引导提问"和"引导追问"，真实反映学习路径

## 实践建议

### title（一句话总结）编写要点

- 描述认知跃迁：从"X"到"Y"
- 包含核心方法或框架
- 示例：
  - "从'买便宜'到'买好公司'的认知跃迁"
  - "执行意图：If-Then计划的认知跃迁"

### summary（能力要点）编写要点

1. **核心跃迁**：一句话描述思维转变（从"X"到"Y"）
2. **掌握的内容**：我真的理解并掌握了什么（用编号列出）
3. **深刻思考**：得出了什么深刻的洞察（用编号列出3-5个）
4. **关键节点**：为什么会这样想（列出思考路径中的关键时刻）

### details（详细思考过程）编写要点

1. **每个能力独立成段**，用`---`分隔
2. **层级结构**：能力定义 → 体现在深刻洞察 → 认知转变过程
3. **用项目符号标记步骤**：认知转变过程用`-`标记
4. **突出突破点**：使用"突破点："标注关键时刻
5. **生活类比**：用熟悉场景验证理解

### 内容精简原则

1. **删除重复能力**：如果多个能力描述类似，合并或删除
2. **聚焦关键能力**：只记录真正带来认知跃迁的核心能力
3. **避免啰嗦**：不记录试错、失败、无关细节
4. **结构化呈现**：使用项目符号、编号、缩进

## 两阶段总结法

由于直接从对话中按"能力"格式总结难度较大，推荐使用两阶段总结法：

### 阶段1：提取问题（中间格式）

**目标**：从对话中识别出所有关键问题，按问题组织。

**Prompt**：
```python
"""
请从以下对话中提炼出关键问题，按照以下结构组织：

问题：[问题标题]

- 正确答案：[最终正确答案]

- 我的初始判断：[开始时的错误认知]
  - 理由：[为什么这么认为]

- 深度思考过程：
  1. [观察到了什么]
  2. [分析原因]
  3. 引导提问："[AI提出了什么关键问题]"
  4. 突破点：[在哪个时刻突然明白了]
  5. [继续推理或验证]
  6. 结论：[最终形成的新认知]

注意：
- 只记录真正带来认知跃迁的问题
- 引导提问必须如实记录对话中的原话
- 突破点是思维转变的关键时刻
"""
```

### 阶段2：提炼能力（最终格式）

**目标**：从阶段1的问题中提炼出可复用的能力，按能力组织。

**Prompt**：
```python
"""
请从以下问题记录中提炼出可复用的能力，按照以下结构组织：

问题背景：
- [最初理解]
- [已有认知]
- [混淆概念]

---

我掌握的能力：

能力1：[能力名称]
能力定义：[这个能力的本质是什么]
体现在深刻洞察：
- [用具体场景说明这个能力]
- [另一个场景]

认知转变过程：
- 原本认知：[开始时的错误认知]
- 引导提问："[AI提出了什么关键问题]"
- 突破点：[在哪个时刻突然明白了]
- 新认知：[最终形成的新认知]
- 类比验证：[用什么生活场景验证了理解]

---

能力2：[能力名称]
能力定义：...
体现在深刻洞察：...
认知转变过程：...

注意：
- 能力名称要简洁，能体现其核心价值
- 能力定义要抽象，不依赖具体场景
- 体现在深刻洞察要用1-2条具体场景说明
- 认知转变过程要完整，从错误到正确
"""
```

**为什么需要两阶段总结法？**

| 维度 | 直接总结（困难） | 两阶段总结法（推荐） |
|------|-----------------|---------------------|
| **难度** | ⭐⭐⭐ 困难 | ⭐⭐ 中等 |
| **准确性** | ⭐⭐ 容易出错 | ⭐⭐⭐⭐ 高 |
| **可复用性** | ⭐⭐⭐ 好 | ⭐⭐⭐⭐ 更好 |
| **AI理解难度** | ⭐⭐⭐ 高 | ⭐⭐ 中等 |

**核心优势**：
1. 降低AI理解难度：阶段1直接提取问题，无需抽象
2. 提高准确性：阶段2基于阶段1的输出，信息更完整
3. 保证格式正确：阶段2明确要求按能力组织
4. 可复用性好：每个能力都有定义和洞察
